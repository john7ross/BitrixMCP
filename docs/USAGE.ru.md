# Руководство по использованию

[English](USAGE.md) · **Русский**

Как управлять инструментами Bitrix24 MCP. Документ не привязан к конкретному
клиенту — предполагается лишь, что твой агент или код умеет говорить по MCP и
вызывать инструменты сервера. Подключение сервера к конкретному клиенту — в
разделе о подключении в README.

## Два слоя

- **Универсальный хребет** — `b24_call`, `b24_batch`, `b24_test_connection`,
  `b24_list_methods`. `b24_call` вызывает *любой* REST-метод, то есть покрывает
  весь API. Бери его, когда не подходит типизированный инструмент или чтобы
  перепроверить его поведение.
- **Типизированные инструменты** — `b24_<домен>_<действие>` (напр. `b24_crm_list`,
  `b24_task_add`). Эргономичные обёртки с корректной пагинацией, фильтрами и
  учётом нюансов Битрикса.

Начинай сессию с `b24_test_connection`, чтобы подтвердить вебхук и увидеть
текущего пользователя, затем `b24_list_methods` — чтобы понять, какие scope есть
у вебхука.

## Авторизация

Каждый инструмент принимает опциональные `webhook_url` и `personal_webhook`.
Порядок резолва: `personal_webhook` > `webhook_url` > заголовок `X-B24-Webhook`
(HTTP-транспорт) > env `BITRIX_WEBHOOK_URL`. Чтобы действовать/писать от имени
конкретного пользователя, передай его `personal_webhook`. Формат всегда
`https://<портал>/rest/<user_id>/<токен>/`.

## Фильтры

Объекты фильтра повторяют Битрикс. У ключей могут быть префиксы-операторы:

| Префикс | Значение | Пример |
|---|---|---|
| (нет) | равно | `{"STAGE_ID": "NEW"}` |
| `>` `<` `>=` `<=` | сравнения | `{">=DATE_CREATE": "2026-01-01"}` |
| `!` | не равно | `{"!STATUS": "5"}` |
| `%` | подстрока | `{"%TITLE": "invoice"}` |

Коды полей различаются по методам (CRM — `UPPER_CASE`; современные `crm.item.*`
и `catalog.*` — `camelCase`). Используй инструменты `*_fields` (напр.
`b24_crm_fields`), чтобы узнать точные коды и id перечислений перед записью.

## Пагинация

Списочные инструменты возвращают конверт:

```json
{ "items": [...], "count": 50, "total": 214, "start": 0,
  "next": 50, "has_more": true, "truncated": false }
```

- Листай вручную, передавая `start` = предыдущий `next`.
- Либо передай `fetch_all: true`, чтобы автоматически пройти все страницы. Это
  ограничено `BITRIX_MAX_PAGES` (по умолчанию 40 страниц ≈ 2000 записей); при
  достижении лимита конверт покажет `truncated: true` — молча выборка не
  обрывается. Всегда добавляй `filter`, чтобы держать `fetch_all` в рамках.

## Ошибки

Ошибки возвращаются как данные, никогда не скрываются:

```json
{ "error": true, "code": "ACCESS_DENIED", "method": "crm.deal.list",
  "message": "Access denied." }
```

Частые коды: `ACCESS_DENIED` (у действующего пользователя нет прав на портале —
не баг; scope у вебхука необходим, но недостаточен), `ERROR_METHOD_NOT_FOUND`
(модуль не установлен), `B24_READONLY` (запись заблокирована read-only-режимом),
`NO_WEBHOOK` (вебхук не резолвится), `TIMEOUT`.

## Режим только чтение

Установи `BITRIX_READ_ONLY=1`, чтобы отклонять каждый write-метод ещё до отправки
на портал (чтение продолжает работать). Полезно, чтобы дать доступ только на
чтение или на время отладки. Сними переменную, чтобы разрешить запись.

## Batch

`b24_batch` выполняет до 50 вызовов одним запросом, с обратными ссылками:

```json
{ "commands": [
    {"key": "deal", "method": "crm.deal.add", "params": {"fields": {"TITLE": "New"}}},
    {"key": "note", "method": "crm.timeline.comment.add",
     "params": {"fields": {"ENTITY_ID": "$result[deal]", "ENTITY_TYPE": "deal", "COMMENT": "created"}}}
  ], "halt": true }
```

`$result[key]` / `$result[key][field]` подставляют вывод более раннего вызова.

## Рецепты

- **Сделки, созданные в этом месяце:**
  `b24_crm_list` entity=`deal`, filter `{">=DATE_CREATE":"2026-07-01"}`, select `["ID","TITLE","OPPORTUNITY","STAGE_ID"]`.
- **Расшифровать код стадии сделки в имя:**
  `b24_crm_status_list` entity_id=`DEAL_STAGE` (или `DEAL_STAGE_7` для воронки 7).
- **Задачи в колонке Scrum-доски:** `b24_scrum_board` group_id=… — получить
  активный спринт + стадии, затем `b24_tasks_list` filter `{"GROUP_ID":…, "STAGE_ID":…}`.
- **Создать задачу и записать время:** `b24_task_add` → затем `b24_task_elapsed_add`.
- **Скачать файл с Диска:** `b24_disk_file_content` file_id=… (возвращает base64;
  ограничено `max_size_mb`).
- **Написать в чат:** `b24_im_message_add` dialog_id=`chat123` или id пользователя.

## SPA / Смарт-процессы

Для элементов Смарт-процессов передавай `entity_type_id` в CRM-инструменты — они
автоматически переключаются на современный API `crm.item.*` (напр. `b24_crm_list`
entity_type_id=1030).
